<objective>
Add variable scroll physics per section type, transition membrane resistance mechanics, and progressive lazy-loading of section content via IntersectionObserver.

Purpose: The core scroll engine from Plan 01 scrolls uniformly. This plan adds the depth-based feel -- the sensation of diving deeper with increasing resistance and distinct physical qualities per section. It also adds performance infrastructure (lazy mounting) that later phases need for heavy 3D/content sections.

Output: A scroll experience where surface feels fluid, mid-depth feels denser, transitions have build-and-release resistance, and deep sections feel calm. Sections lazy-mount as they approach the viewport.
</objective>

  <name>Task 1: Variable scroll physics and transition membrane resistance</name>
  <files>src/lib/scroll-physics.ts, src/components/ScrollEngine.tsx, tests/scroll.spec.ts</files>
  <action>
    1. Extend `src/lib/scroll-physics.ts` with transition resistance configuration:
       - Add `TransitionResistanceConfig` type: `{ zone: [number, number], basePeak: number, releasePoint: number }`
       - Export `TRANSITION_RESISTANCE` config:
         - `'transition-1': { zone: [0, 1], basePeak: 0.4, releasePoint: 0.8 }` -- moderate resistance
         - `'transition-2': { zone: [0, 1], basePeak: 0.25, releasePoint: 0.8 }` -- ~50% heavier (lower basePeak = more resistance)
       - Add `ASCENT_RESISTANCE_MULTIPLIER = 0.5` constant (ascending = 50% of descending resistance per user decision)
       - Verify existing SCROLL_PHYSICS values are correct for the ~30% variation:
         - Surface scrub 1 (baseline)
         - Pockets scrub 1.2 (~20% heavier feel)
         - Projects scrub 1.5 (~50% heavier)
         - Transitions scrub 0.5 (quick passages)

    2. Add membrane resistance function to `src/components/ScrollEngine.tsx`:
       - Create `getTransitionResistance(progress: number, direction: number, transitionId: string): number` function:
         a. Look up config from TRANSITION_RESISTANCE by transitionId
         b. If not a transition section, return 1 (no resistance)
         c. Direction multiplier: `direction === -1 ? ASCENT_RESISTANCE_MULTIPLIER : 1.0`
         d. Build phase (progress < releasePoint): resistance increases via sine curve
            `1 - (1 - basePeak) * Math.sin(buildProgress * Math.PI * 0.5) * dirMultiplier`
         e. Release phase (progress >= releasePoint): resistance drops rapidly back to 1 (the "pop")
            `current + (1 - current) * releaseProgress`
         f. Return the multiplier (0-1 range, lower = more resistance)

    3. Integrate membrane resistance into ScrollEngine's Lenis instance:
       - On each Lenis scroll event, check if current section is a transition (from scrollStore.section)
       - If in a transition, dynamically adjust Lenis's `wheelMultiplier` option to match the resistance value
       - Use `lenis.options.wheelMultiplier = resistanceValue` (Lenis allows runtime option mutation)
       - When leaving a transition zone, reset `wheelMultiplier` to 1
       - IMPORTANT: The resistance is physics-only -- no visual feedback (that's Phase 6's job per user decision)

    4. Add variable scroll feel tests to `tests/scroll.spec.ts`:
       - "variable -- different scroll distances per section type": Scroll through surface and pocket-1, measure the scroll distance (end values) needed to traverse each. Verify pocket-1 requires more scroll distance than surface (1.5x vs 1x).
       - "membrane -- transition zones have resistance": Scroll into transition-1, verify that `window.__scrollStore.section` updates to 'transition-1'. The resistance itself is hard to test programmatically (it affects wheel events), so test that the transition zone exists and is recognized by the scroll store.
       - Update existing tests if needed to account for variable scroll distances.

       - In `useEffect`, create IntersectionObserver with the rootMargin

       - IMPORTANT: Never unmount once mounted -- unmounting breaks ScrollTrigger measurements (documented pitfall from research)
       - Render: `<div ref={ref}>{mounted ? children : null}</div>`
       - The wrapper div must NOT break the ScrollTrigger pin target. It should be transparent to layout -- add `style={{ display: 'contents' }}` to avoid injecting an extra layout box. BUT test this carefully: `display: contents` can break ref targeting. If it causes issues, use a plain div without display:contents and ensure it doesn't break pin-spacer.
       - Actually, the safer approach per research: lazy-mount section CHILDREN, not the section shells themselves. The SectionShell with its height must always be in the DOM for ScrollTrigger. LazySection wraps the children INSIDE SectionShell.
